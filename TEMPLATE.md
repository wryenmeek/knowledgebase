# Knowledgebase Template — Setup Guide

This repository is a **GitHub Template Repository**. Click **"Use this template"** on
GitHub to create a new instance, then follow the steps below to replace the
domain-specific content with your own while keeping the framework intact.

---

## Two-layer architecture

The repository has two distinct layers. Understanding the boundary is the first thing
to do before changing anything.

### Framework layer — keep as-is

These directories are reusable across any domain. Do not delete them.

| Path | Role |
|------|------|
| `scripts/` | Ingest, index, lint, query, and monitoring scripts |
| `tests/` | Test suite — must pass green after you replace content |
| `.github/` | Agent skills, personas, hooks, and CI workflows |
| `schema/` | Page, taxonomy, ontology, metadata, and ingest contracts |
| `docs/decisions/` | Architecture Decision Records |
| `docs/architecture.md` | System design reference |
| `docs/user-guide.md` | Operator guide |
| `docs/mvp-runbook.md` | CI workflow runbook |
| `pyproject.toml` | Python package configuration |
| `.pre-commit-config.yaml` | Pre-commit hook configuration |
| `mkdocs.yml` | Documentation site configuration |
| `wiki/search.md` | Pagefind search page (framework) |
| `wiki/tags.md` | MkDocs tags page (framework) |
| `wiki/CONTEXT.md` | Domain vocabulary — **edit heavily** |
| `CONTEXT.md` | Repo-level context — **edit heavily** |
| `AGENTS.md` | Agent guardrails — **edit heavily** |
| `README.md` | Repo overview — **edit heavily** |

### Content layer — replace with your domain

These paths contain the domain-specific knowledge from the template instance.
The `init.py --fresh` script wipes them automatically (see [Quick start](#quick-start)).

| Path | What to replace |
|------|-----------------|
| `wiki/analyses/` | Synthesized analysis pages |
| `wiki/concepts/` | Concept/entity pages |
| `wiki/entities/` | Named entity pages |
| `wiki/sources/` | Source synthesis pages |
| `wiki/index.md` | Regenerated by `update_index.py` |
| `wiki/log.md` | Append-only audit log — reset on init |
| `raw/inbox/` | Your source documents go here first |
| `raw/processed/` | Post-ingest immutable artifacts |
| `raw/assets/` | Checksummed media/binary assets |
| `raw/rejected/` | Intake rejection records |
| `raw/github-sources/` | GitHub source registry files |
| `raw/drive-sources/` | Google Drive source registry files |
| `raw/processed/SPEC.md` | Domain assumptions — **edit before first ingest** |

## Quick start

### 1. Clone your new repo

```bash
git clone https://github.com/YOUR-ORG/YOUR-REPO.git
cd YOUR-REPO
```

### 2. Install dependencies

Core scripts require Python 3.11+. `qmd` is used for local search.

```bash
pip install -e ".[dev]"
pre-commit install
```

Optional — Google Drive monitoring:

```bash
pip install -e ".[drive-monitor]"
```

To verify the dependency install is complete:

```bash
python3 -m pytest tests/ -q
```

All tests must pass on a fresh clone before you replace any content.

### 3. Wipe domain content and scaffold your instance

```bash
python3 scripts/init.py --fresh
```

This will:
- Ask for confirmation before deleting anything
- Wipe all content-layer directories (see table above)
- Reset `wiki/log.md` and `wiki/index.md` to empty stubs
- Create a sample source document at `raw/inbox/example-policy.md`
- Run `pytest` to confirm the framework is clean

### 4. Edit the four files you must update

Before your first ingest, update these files with your domain:

**`raw/processed/SPEC.md`** — Domain assumptions that govern ingest and synthesis.
Replace every `TODO` section with your domain specifics (terminology, sensitivity
levels, authority sources).

**`AGENTS.md`** — Write-surface matrix and guardrails. Update the mission statement
and any domain-specific path references.

**`CONTEXT.md`** — Repo-level context. Replace the domain vocabulary and invariants
with your subject area.

**`wiki/CONTEXT.md`** — Wiki-level context. Replace the taxonomy and entity terms.

**`README.md`** — Project overview. Replace with your domain description.

### 5. Run your first ingest

Once `raw/processed/SPEC.md` is updated, ingest the sample document to prove the
pipeline end-to-end:

```bash
python3 scripts/kb/ingest.py \
  --source raw/inbox/example-policy.md \
  --wiki-root wiki \
  --schema AGENTS.md
```

Then rebuild the index and run lint:

```bash
python3 scripts/kb/update_index.py --wiki-root wiki --write
python3 scripts/kb/lint_wiki.py --wiki-root wiki --strict
```

## CI service credentials

The framework includes two optional monitoring workflows that require external
credentials. Skip this section if you are not using GitHub or Google Drive source
monitoring.

### Google Drive monitoring (CI-6)

Requires a GCP service account with Drive API access stored as the `GDRIVE_SA_KEY`
repository secret. See the full setup instructions in
[`docs/ideas/cloneable-template.md` § CI Service Credentials Setup](docs/ideas/cloneable-template.md#ci-service-credentials-setup).

### GitHub source monitoring (CI-5)

Requires a GitHub App with `contents: write` installed on the repo, stored as
`GH_APP_ID` and `GH_APP_PRIVATE_KEY` secrets (note: GitHub bans the `GITHUB_`
prefix for repository secrets). See
[`docs/ideas/cloneable-template.md` § CI Service Credentials Setup](docs/ideas/cloneable-template.md#ci-service-credentials-setup)
for the step-by-step CLI instructions.

### Required GitHub environment

Both CI-5 and CI-6 write jobs require a `protected-pr-write` GitHub Actions
environment:

```bash
gh api -X PUT "repos/YOUR-ORG/YOUR-REPO/environments/protected-pr-write"
```

## Verify your setup

After completing the steps above, run the full test suite:

```bash
python3 -m pytest tests/ -q
```

All 1 000+ tests should pass. If any fail, check that:

- You did not accidentally delete any framework-layer files
- `raw/processed/SPEC.md` exists and has valid YAML frontmatter
- `wiki/log.md` and `wiki/index.md` exist with the stubs created by `init.py`

## What to expect from the framework

Once your first source is ingested you can:

- **Query** — ask questions via `scripts/kb/qmd_preflight.py`
- **Lint** — `scripts/kb/lint_wiki.py --wiki-root wiki --strict`
- **Rebuild index** — `scripts/kb/update_index.py --wiki-root wiki --write`
- **Monitor GitHub sources** — `scripts/github_monitor/check_drift.py`
- **Monitor Drive sources** — `scripts/drive_monitor/check_drift.py`

The [User Guide](docs/user-guide.md) has the full operator walkthrough.
The [Runbook](docs/mvp-runbook.md) documents all CI workflows.
